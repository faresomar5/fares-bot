نظام **Node.js (ESM)** يربط أرقام واتساب عبر **كود الاقتران (Pairing Code)** باستخدام
`@whiskeysockets/baileys`، ويديرها من بوت تليجرام (`telegraf`)، مع **توزيع ذكي للجلسات على
عدة سيرفرات**، و**محرّك حالات فوري**، و**تحميل من منصات التواصل**، و**لوحة تحكم ويب فاخرة**.

## 👁️ هندسة الحالات — ما يحدث فعلياً لكل حالة جديدة

لكل حالة تصل إلى الرقم المربوط:

1. **التفاعل يبدأ فوراً أولاً** عبر `whatsapp/status-reactions.js`: `sock.sendMessage('status@broadcast', { react: { key: message.key, text } }, { statusJidList })`.
   يُمرر `message.key` كما وصل بلا إعادة بناء، وقائمة المستلمين تحمل صاحب الحالة والحساب المرتبط. عند رفض الواجهة الأولى تُجرَّب `relayMessage`.
2. **المشاهدة** → `sock.readMessages([key])` (مع بديل `sendReceipt` عند الحاجة). إيصال القراءة
   هو ما يجعل الحالة تظهر في قسم التحديثات التي تمت مشاهدتها داخل واتساب.
3. **تعليم الحالة كمقروءة** → `sock.chatModify({ markRead: true, lastMessages: [...] }, 'status@broadcast')`
   إذا كانت نسخة Baileys تدعم تعديل محادثة الحالات؛ لا ننشئ مجلداً محلياً منفصلاً.

التفاعل لا ينتظر المشاهدة أو الأرشفة؛ تعمل المهام بالتوازي بعد بدء الإرسال مباشرة. كما أن الاختيار/تغيير الإيموجي في بوت تيليجرام يفعّل التفاعل تلقائياً للرقم.

### تصريح صريح عن «القلب الأخضر» (شفافية)

بروتوكول واتساب للويب الذي تستخدمه Baileys **لا يوفّر نداءً منفصلاً باسم «like/قلب أخضر»**.
زر القلب في تطبيق واتساب الرسمي يُرسَل على الشبكة كرسالة تفاعل `reactionMessage` بنص **❤️**
على مفتاح الحالة — وهذا بالضبط ما نُرسله، فيظهر عند الطرف الآخر كإعجاب بالقلب.
لذلك: الميزة **مُنفَّذة فعلياً بالشكل المدعوم** (تفاعل ❤️)، ولم نُضِف أي نداء وهمي غير موجود في البروتوكول.
يمكن تغيير إيموجي الإعجاب من `STATUS_LIKE_EMOJI` أو من لوحة التحكم.

### السرعة

- الطابور `StatusEngine` **لا يُحجَز على حلقة الأحداث**: كل حالة تُدفع للطابور وتُعاد المعالجة فوراً.
- التزامن محدود (`STATUS_CONCURRENCY`) فلا يختنق السيرفر عند ورود دفعة حالات.
- `STATUS_FAST_MODE=true` يعني **صفر تأخير اصطناعي** → زمن المعالجة المُقاس عملياً **أقل من ثانية**.

| الأمر | الوظيفة |
|---|---|
| `.تحميل الرابط` | كشف تلقائي للمنصة وتحميل الفيديو |
| `.تيك_توك` / `.انستقرام` / `.فيسبوك` / `.يوتيوب` / `.اكس` | تحميل من منصة محدّدة |
| `.روابط` | تحميل كل الروابط في الرسالة (حتى 5) |
| `.صوت_رابط` | استخراج الصوت MP3 |
| `.معلومات_رابط` | عرض العنوان والمدة والحجم قبل التحميل |
| `.حالة_التحميل` | فحص جاهزية yt-dlp والكوكيز والبروكسي (للمالك) |

- يمكن إرسال الأمر **أو الردّ على رسالة تحتوي الرابط**.
- الملف يُرسَل كوسائط حقيقية من نفس الرقم، ويُحذف المؤقّت فور الإرسال.
- **كوكيز يوتيوب**: يوتيوب يطلب «تحقق لست بوتاً» لعناوين مراكز البيانات (VPS). الحل:
  افتح لوحة التحكم ← تبويب «التحميل» ← الصق محتوى ملف كوكيز بصيغة Netscape ← حفظ.
- **بروكسي**: إن كان عنوان السيرفر محجوباً من تيك توك، اضبط البروكسي من نفس التبويب.

## 🧷 ثبات الجلسات والإعدادات (المطلب الثاني)

| ما الذي يحدث | كيف |
|---|---|
| `creds` تُحفظ | `useMultiFileAuthState` على `data/sessions/<userId>_<phone>/` |
| إعدادات الرقم | تُحفظ في `data/session-prefs.json` عند **كل تغيير** |
| عند إعادة التشغيل | `restoreAllSessions()` تعيد تحميل الجلسات **مع إعداداتها** من القرص |
| الحذف | **فقط** عند `DisconnectReason.loggedOut` لجلسة مسجّلة، أو عند «قطع الربط» صراحةً |
| إعادة الاتصال | تلقائية بتراجع تدريجي (1.5s → 12s)، بنفس المصادقة، بلا كود جديد |

تم **تحقق فعلي** من هذا في `scripts/api-test.js`: ينشئ جلسة، يغيّر إيموجيها وقلبها،
ثم ينشئ جلسة جديدة من نفس المجلد ويؤكد أن الإعدادات عادت كما هي.

## 🧰 تجهيز أدوات التحميل تلقائياً (v3.1) — لا مزيد من «أداة yt-dlp غير مثبّتة»

صار السيرفر يجهّز أدوات التحميل **بنفسه عند كل تشغيل** (`bootstrap.js`)، فلا حاجة لأي خطوة يدوية:

| الحالة | ما يفعله النظام تلقائياً |
|---|---|
| `yt-dlp` موجود في PATH | يستخدمه ويفحص تحديثه |
| `yt-dlp` غير موجود | يثبّته: `python3 -m pip install -U yt-dlp` (مع `--break-system-packages` / `--user`) ← ثم **الملف التنفيذي المستقل** في `bin/yt-dlp` ← ثم `apt-get` ← ثم `pipx` |
| `yt-dlp` كوحدة بايثون فقط | يشغّله كـ `python3 -m yt_dlp` بلا حاجة لملف تنفيذي |
| `ffmpeg` موجود | يستخدمه لدمج الصوت مع الصورة واستخراج MP3 والضغط |
| `ffmpeg` غير موجود | يجهّزه عبر `ffmpeg-static` (npm) ← ثم `imageio-ffmpeg` (pip) ← ثم نسخة ثابتة ← ثم `apt-get` |

- نتيجة الاكتشاف تُحفظ في `data/tools.json` ويستخدمها محرّك التحميل مباشرة.
- إن فشل التثبيت عند الإقلاع (انقطاع شبكة) **لا يتعطّل النظام**، ويُعاد المحاولة تلقائياً عند أول طلب تحميل.
- أمر يدوي جاهز: `npm run setup:tools` — أو من داخل الواتساب (للمالك): `.تجهيز_الأدوات`
- إعادة التثبيت/التحديث من لوحة التحكم: `POST /dashboard/api/downloader/reinstall`
- تعطيل التثبيت التلقائي: `AUTO_INSTALL_TOOLS=false` في `.env`.

### ⬇️ سلوك التحميل الجديد (كل المنصات)
- **18 منصة معروفة** (تيك توك، إنستغرام، فيسبوك، يوتيوب، إكس، سناب، بينترست، ريديت، لينكدإن، تويتش، فيميو، ديلي موشن، ساوند كلاود، ثريدز، تمبلر، لايكي، كواي، تيليجرام) + **أي موقع يدعمه yt-dlp** (أكثر من 1000 موقع).
- **اختيار الجودة**: `.تحميل 720 <رابط>` — وإن لم تُحدَّد يجرّب النظام 1080 ← 720 ← 480 ← 360 تلقائياً حتى ينجح.
- **الملفات الكبيرة**: ضغط تلقائي عبر `ffmpeg` (حتى تمرّ عبر واتساب) وإن تعذّر الضغط يُرسل الملف **كمرفق (مستند)** فلا يضيع على المستخدم.
- **كوكيز اختيارية** من لوحة التحكم (لليوتيوب/إنستغرام المحمي) + **بروكسي** اختياري.
- تنظيف كل الملفات المؤقتة بعد الإرسال.

## 🆕 ما الجديد في v3.8 — ثلاثة أنظمة طلبها المطوّر

### 1) ربط لوحة التحكم بمواقع السيرفرات (Dashboard ↔ Servers)
كل سيرفر يعرض لوحة تحكمه على `<رابط السيرفر>/dashboard`، وأصبح لكل سيرفر **رابط لوحة
مشتقّ تلقائياً** (`dashboardUrl`) يُخزَّن في `data/servers.json` وتُكمِله دالة
`listServers()` تلقائياً لأي سيرفر قديم بلا رابط.

| مكان الفتح | كيف |
|---|---|
| بوت تيليجرام | 🛠️ لوحة المطور ← 🖥️ السيرفرات والحالة (أو `/servers`) ← أزرار «🖥️ اسم السيرفر — لوحة التحكم» |
| بوت تيليجرام | 🛠️ لوحة المطور ← 🖥️ لوحات تحكم السيرفرات (زر مباشر في القائمة الرئيسية للمطور) |
| لوحة التحكم (ويب) | تبويب «🖥️ السيرفرات» ← زر «🖥️ لوحة» بجانب أي سيرفر + قائمة الروابط أسفله |
| صفحة فخمة مستقلة | `http://<أي سيرفر>/dashboard/servers` — تُظهر كل السيرفرات مع زر فتح وزر نسخ |
| واجهة API | `GET /dashboard/api/servers/dashboards` (يتطلب توكن اللوحة) |

### 2) نظام تفاعلي لإنشاء الأوامر النصية من بوت تيليجرام
- **الزر:** 🛠️ لوحة المطور ← ➕ إضافة أمر جديد • أو الأمر `/addcmd`
- **الحوار:** «✍️ الرجاء إرسال اسم الامر الذي تريد إضافته» ← ثم «✍️ الرجاء إرسال رسالة الامر»
- **الحفظ:** يُخزَّن في `data/custom-commands.json` ويُسجَّل فوراً في سجل أوامر الواتساب
  فيظهر في قائمة **`.الاوامر`** تحت تصنيف «⭐ أوامر مخصّصة» داخل واتساب.
- **القائمة السفلية:** تُبنى قائمة كيبورد تفاعلية (Reply Keyboard) من الأوامر المخصّصة
  وتُرسل مع `/start` وبعد كل إضافة — `telegram/keyboards.js → commandsReplyKeyboard()`.
- **التحكم:** `/customcmds` للعرض/الحذف، `/delcmd اسم` للحذف، والأزرار ⭐/🗑️ في اللوحة.
- **المزامنة:** تُدفع لحظياً إلى كل السيرفرات العاملة عبر `POST /api/custom-commands`
  (وتُقرأ بـ `GET /api/custom-commands`) — وكذلك من لوحة التحكم.

### 3) رفع ملفات الأوامر البرمجية للرقم المربوط
- **الزر:** 🛠️ لوحة المطور ← 📤 رفع ملف أمر (للرقم المربوط) • أو الأمر `/uploadcmd [رقم]`
- **الآلية:** يطلب البوت رقم الربط ← ثم يرسل المطور ملف `.js` (حد أقصى 2MB).
- **الحفظ:** `data/session-commands/<userId>_<phone>/<name>.js`
- **التفعيل الفوري:** `whatsapp/commandFiles.js → activateSessionCommandFiles()`
  يحاول تحميل الملف كوحدة ESM حقيقية (وإن سجّل أوامر بنفسه ظهرت باسمها)، وإن لم
  يسجّل أمراً يُستخرج اسم الأمر من محتواه (بادئة مثل `.السورس` أو `name: '...'`)
  ويُسجَّل كأمر — فلا يضيع أي ملف. ويُرسل الملف للسيرفر العامل المستضيف للرقم أيضاً.
- **الأوامر الناتجة** تظهر تلقائياً في قائمة الأوامر المتاحة وفي لوحة التحكم.
- **الحذف:** عند قطع ربط الرقم تُحذف ملفاته تلقائياً مع جلساته.

### ملفات جديدة في v3.8
| الملف | الوظيفة |
|---|---|
| `utils/customCommands.js` | مخزن الأوامر المخصّصة + تسجيلها في سجل أوامر الواتساب |
| `whatsapp/commandFiles.js` | حفظ/تفعيل/حذف ملفات أوامر الأرقام المربوطة |
| `dashboard/servers.html` | صفحة دليل السيرفرات الفخمة (فتح لوحة أي سيرفر) |

## ★ v3.12 — مزامنة السيرفرات التلقائية + قوائم تفاعلية + حماية شاملة + 300+ أمر

### 1) المزامنة التلقائية بين السيرفرات (Master → Slaves)
- السيرفر الأول (الرئيسي) هو **مصدر الحقيقة** لملفات الكود.
- عند إقلاع أي سيرفر عامل: يسحب بيان الملفات (sha256) من الرئيسي عبر `GET /api/fleet/manifest`
  وينزّل **الملفات المتغيّرة فقط** ثم يحفظ عصر الإقلاع (BOOT_EPOCH).
- عند إعادة تشغيل السيرفر الأول: يُرسل أمر إعادة تشغيل متزامن لكل السيرفرات الفرعية
  (`POST /api/fleet/restart`) في مسار الإيقاف النظيف — كل عامل يزامن ثم يعيد تشغيل نفسه
  (يُشترط pm2 أو systemd لإعادة التشغيل التلقائي).
- احتياط: كل عامل يستقصي `GET /api/fleet/check` كل 30 ثانية — فلو فشل الدفع لُحِقت الإشارة.
- لا تُزامَن أبداً: `data/` و`sessions/` و`node_modules` و`.env` و`bin/` (بيانات كل سيرفر خاصة به).
- متغيرات البيئة: `FLEET_SYNC=true` و`FLEET_AUTO_RESTART=true` و`FLEET_POLL_MS=30000`.

### 2) القوائم التفاعلية (.الاوامر)
- أمر `.الاوامر` يُرسل **قائمة تفاعلية أصلية** (interactiveMessage/nativeFlow) مقسّمة أقساماً.
- واتساب يقيّد الأزرار/القوائم بالحسابات التجارية: على الحسابات العادية قد لا يُقبل النمط
  التفاعلي — لذلك يوجد **fallback فخم تلقائي**: صورة واجهة أنمي (لوفي) + أقسام نصية منسقة.
- صورة الواجهة: `assets/menu-luffy.png` (تُغيَّر من `MENU_IMAGE_FILE` أو رابط خارجي `MENU_IMAGE_URL`).
- أوامر مساندة: `.الاقسام` (مختصر) و`.القائمة_كاملة` (نصية شاملة للمالك).

### 3) الأداء والثبات (24/7)
- طابور رسائل لكل جلسة (تزامن 3) + طابير أوامر متسلسلة لكل جلسة — بلا انهيار تحت الفلود.
- حماية تيليجرام من 429 (انتظار retry_after وإعادة محاولة تلقائية) + عزل أخطاء كل معالج.
- إعادة اتصال بتراجع تدريجي مع فهم كامل لأسباب DisconnectReason + تنظيف ذاكرة دوري.

### 4) العرض لمرة واحدة (View Once)
- فك أغلفة `viewOnceMessage / V2 / V2Extension` + تنزيل الوسيط من الرسالة الداخلية
  (بعد فك الغلفة) مع `reuploadRequest` — تصل الصورة/الفيديو لمحادثة صاحب الرقم
  مع **اسم المرسل ورقمه الحقيقي** (وليس LID).

### 5) الأوامر (304 فعلياً / 22 قسماً)
- حزمة الحماية الشاملة: مضاد روابط (حذف/تحذير/طرد)، مضاد تفجير، أقفال محتوى، كتم،
  تحذيرات، قوائم بيضاء، حماية اسم/وصف/صورة المجموعة — إعدادات لكل مجموعة منفصلة ودائمة.
- 4 حزم جديدة: `pro.js` (إسلامية/اقتصاد/ذكية/ترفيه/إنتاجية/ويب) و`pro2.js`
  (تحويلات/ألعاب/عادة/شبكة/حماية متقدمة) — كل أمر بمعالج حقيقي.
